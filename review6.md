## 2. Цель работы

Организовать веб-интерфейс DebtTrack с помощью шаблонов Django: выделить общий
каркас и повторяемые фрагменты, разместить шаблоны по приложениям, перейти на
именованные маршруты и подключить CSS и JavaScript как статические файлы.

## 3. Структура шаблонов

В каталоге `templates` сохранён общий `base.html` и создан фрагмент
`includes/navigation.html`. Базовый шаблон содержит HTML-каркас, подключение
статики, текстовый бренд, навигацию, блок содержимого и подвал.

Шаблоны страниц перенесены в приложения:

- `homepage/templates/homepage` содержит главную, список дисциплин и 404;
- `students/templates/students` содержит список, страницу студента и фрагмент
  карточки;
- `debts/templates/debts` содержит список, страницу задолженности и фрагмент
  статуса.

Страницы используют `{% extends %}` и блоки `title` и `content`, а общие части
подключаются через `{% include %}`. Фильтр `length` выводит размеры коллекций,
фильтр `default` задаёт резервные значения.

## 4. Представления и маршрутизация

Все веб-представления используют `render()` и передают данные через контекст.
HTML в Python не формируется. Для списка студентов представление отдельно
готовит число активных задолженностей, не изменяя объекты предметной области.

Для приложений заданы пространства имён `homepage`, `students` и `debts`.
Ссылки строятся тегом `{% url %}`. Маршруты подробных страниц сохраняют
строковые идентификаторы, соответствующие формату существующих JSON-данных.
Отсутствующие студенты и задолженности отображаются теми же подробными
шаблонами со статусом HTTP 404.

## 5. Статические файлы

В `homepage/static/homepage` добавлены минималистичные стили и JavaScript.
Шапка остаётся без цветного фона и отделяется нижней границей. В содержимом нет
карточек с рамками и разноцветных статусов. Скрипт выводит текущий год в
подвале. Бренд DebtTrack выполнен текстовым заголовком; отдельный файл
логотипа не используется.

## 6. Сохранение архитектуры приложения

Веб-интерфейс остаётся доступным только для чтения. Данные загружаются функцией
`storage.load_data()` из JSON-каталога. Django ORM, собственная база данных,
формы и авторизация не добавлялись. Консольное приложение, предметные классы и
JSON-хранилище сохранены.

## 7. Проверка результата

Веб-тесты проверяют базовый шаблон, навигацию, подключение статики, шаблоны и
включаемые фрагменты приложений, вывод данных, пустые коллекции и ответы 404.

Итоговые команды проверки:

- `python manage.py check`;
- `python manage.py findstatic homepage/css/style.css`;
- `python manage.py findstatic homepage/js/main.js`;
- `flake8 .`;
- `pytest -v`;
- `git diff --check`.

## 8. Вывод

В ходе ПР6 интерфейс DebtTrack переведён на структурированные шаблоны Django.
Общий каркас, навигация и повторяемые элементы вынесены в отдельные шаблоны,
страницы распределены по приложениям, а оформление и поведение подключены как
статические файлы. Это уменьшило дублирование и разделило подготовку данных и
их отображение без изменения предметной модели и формата хранения.
