## 2. Цель работы

Преобразовать проект ПР2 в объектно-ориентированную систему без потери ранее реализованной функциональности. Выделить основные сущности предметной области, создать классы, организовать связи между объектами, адаптировать JSON-хранилище, пользовательский интерфейс и автоматические тесты.

## 3. Анализ предметной области

В системе учёта академической задолженности выделены четыре основные сущности.

| Класс | Основные атрибуты | Поведение |
|---|---|---|
| `Student` | `id`, `name`, `group_number`, `record_book` | Строковое представление; создание из словаря; преобразование в словарь |
| `Discipline` | `id`, `name`, `teacher`, `semester` | Строковое представление; создание из словаря; преобразование в словарь |
| `Debt` | `id`, `student`, `discipline`, `date_created`, `is_closed`, `closed_at` | Закрытие задолженности; проверка повторного закрытия; сериализация |
| `Retake` | `id`, `debt`, `retake_date`, `result` | Представление пересдачи; проверка даты; сериализация |

Коллекции словарей из ПР2 заменены объектными коллекциями: `list[Student]`, `list[Discipline]`, `list[Debt]` и `list[Retake]`.

Связи реализованы через ссылки на объекты. Задолженность хранит объекты студента и дисциплины, поэтому доступны выражения `debt.student.name` и `debt.discipline.name`. Пересдача хранит объект задолженности, а связанный идентификатор доступен через `retake.debt.id`.

## 4. Переработка проекта

Операции, относящиеся к одному объекту, перенесены в методы классов. Например, задолженность закрывается методом `Debt.close()`, который также запрещает повторное закрытие. Операции над коллекциями сохранены в виде функций: добавление и поиск студентов, создание задолженностей и пересдач, подсчёт задолженностей, фильтрация, сортировка и поиск студента с наибольшим количеством долгов.

Для работы с JSON реализованы методы `from_data()` и `to_data()`. При сохранении объекты преобразуются в словари, а связи записываются идентификаторами `student_id`, `discipline_id` и `debt_id`. При загрузке идентификаторы разрешаются обратно в ссылки на объекты.

Сохранена совместимость с данными ПР2. Если отдельный файл дисциплин отсутствует, дисциплины создаются в памяти по названиям из старых задолженностей и пересдач. Старые поля `full_name`, `group`, `created_at` и `status` преобразуются в новую модель. После сохранения данные записываются в формате ПР3.

Модуль `main.py` переведён на объектные коллекции и полное сохранение связанных данных. Добавлен модуль `disciplines.py`. Тесты адаптированы к атрибутам и связям объектов; добавлены проверки создания классов, строковых представлений, закрытия задолженности, взаимодействия объектов и сериализации. `README.md` дополнен описанием классов, структуры, хранения данных и команд запуска.
