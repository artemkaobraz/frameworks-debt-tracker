## 2. Цель работы

Расширить проект DebtTrack веб-интерфейсом на Django, сохранив консольное
приложение и объектную модель ПР3. Настроить маршрутизацию, реализовать
представления для просмотра данных из JSON и добавить общий каркас страниц.

## 3. Структура Django-проекта

В корне репозитория создан `manage.py`, а в пакете `debtly` размещены настройки,
корневая маршрутизация и точки входа WSGI/ASGI. Добавлены три приложения:

- `homepage` — главная страница, список дисциплин и обработчик 404;
- `students` — список студентов и подробная страница студента;
- `debts` — список задолженностей и подробная страница задолженности.

В настройках зарегистрированы приложения, выбран русский язык и часовой пояс
`Europe/Moscow`. Для локального запуска разрешены `localhost`, `127.0.0.1` и
тестовый хост Django. В зависимости добавлен `Django==5.2.*`; при выполнении
работы установлена версия 5.2.18.

## 4. Реализация веб-интерфейса

Реализованы страницы `/`, `/students/`, `/students/<student_id>/`, `/debts/`,
`/debts/<debt_id>/` и `/disciplines/`. Списки содержат ссылки на подробные
карточки. Карточка студента показывает его группу, число активных долгов и все
связанные задолженности. Для отсутствующего студента или задолженности
возвращается код 404. Неизвестные URL при отключённом режиме отладки выводят
собственную страницу ошибки.

Представления используют шаблонизатор Django. Общий HTML5-каркас, навигация и
минималистичные стили находятся в `templates/base.html`, а шаблоны страниц
наследуют его. Динамические данные автоматически экранируются Django.

Веб-слой использует существующую функцию `storage.load_data()` и каталог
`data`, расположенный относительно `BASE_DIR`. Поэтому сохранена совместимость
с данными ПР3, включая старый формат без отдельного `disciplines.json`.
Строковые идентификаторы поддерживаются маршрутами без преобразования в числа.

## 5. Сохранение функциональности ПР3

Классы предметной области, JSON-хранилище и `main.py` не заменялись Django ORM.
Веб-интерфейс работает только на чтение. Формы, авторизация и операции создания,
изменения или удаления через браузер не добавлялись. Консольное приложение и
существующие тесты ПР3 продолжают работать.

`README.md` дополнен описанием Django-структуры, страниц, представлений,
установки, запуска, проверок и дальнейшего развития проекта.

## 6. Проверка результата

Добавлены автоматические тесты веб-интерфейса. Они проверяют навигацию,
отображение реальных JSON-данных, страницы списков и карточек, ответы для
неизвестных объектов и пользовательский обработчик 404.

Результаты итоговой проверки:

- `python manage.py migrate --noinput` — стандартные миграции выполнены;
- `python manage.py check` — ошибок конфигурации не обнаружено;
- `flake8 .` — замечаний нет;
- `pytest -v` — **23 теста пройдено**.

Файл SQLite, появившийся при проверочном запуске миграций, не включён в
результат работы: собственные ORM-сущности и база данных DebtTrack в ПР5 не
создавались.

## 7. Вывод

В ходе ПР5 проект DebtTrack получил веб-интерфейс на Django 5.2 с общей
навигацией, собственными минималистичными CSS-стилями в `templates/base.html`,
просмотром студентов, дисциплин и задолженностей, а также корректной обработкой
ошибок 404. Реализация повторно использует модель и JSON-хранилище ПР3, не
нарушая работу консольной версии. Работоспособность подтверждена системной
проверкой Django, Flake8 и полным набором автоматических тестов.
