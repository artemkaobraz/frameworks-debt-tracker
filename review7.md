## 2. Цель работы

Добавить в DebtTrack реляционное хранилище SQLite, перенести в него существующие
данные из JSON и организовать чтение данных веб-интерфейсом с помощью SQL-запросов
без использования Django ORM. Сохранить работу консольной версии приложения.

## 3. Схема базы данных и SQL-запросы

В `sql/schema.sql` созданы таблицы `students`, `disciplines` и `debts`.
Идентификаторы записей представлены целыми первичными ключами, а задолженности
связаны со студентами и дисциплинами внешними ключами. Для признака закрытой
задолженности `is_closed` предусмотрены значения 0 и 1.

Файл `sql/queries.sql` содержит 12 запросов для выборки данных. В них
используются фильтрация `WHERE`, соединения `JOIN`, агрегатные функции,
группировка `GROUP BY`, а также `NOT IN` и `HAVING`. Запросы охватывают списки
студентов и задолженностей, студентов без активных долгов и статистику.

Модуль `db/database.py` открывает файл `data/debt_track.sqlite` по абсолютному
пути, включает проверку внешних ключей и настраивает доступ к полям результата
по имени через `sqlite3.Row`. Подготовленная база данных включена в проект.

## 4. Импорт данных из JSON

Модуль `db/import_json.py` получает исходные данные через существующую функцию
`storage.load_data()`, проверяет идентификаторы и связи задолженностей, создаёт
схему и переносит записи в SQLite. Дисциплины извлекаются в том числе из
вложенных данных, поэтому импорт работает и при отсутствии отдельного файла
`disciplines.json`.

Повторный запуск импорта заменяет ранее загруженные записи без дублирования.
Замена выполняется в транзакции: при ошибке прежнее содержимое базы сохраняется.
Для обновления базы после изменения JSON-данных используется команда
`python -m db.import_json`.

## 5. Веб-интерфейс

Представления приложений `homepage`, `students` и `debts` переведены на чтение
из SQLite через `sqlite3`. Страницы списков и подробные страницы используют
SQL-запросы; маршруты подробных страниц принимают целочисленные идентификаторы.
Шаблоны обновлены для отображения строк результатов запросов.

Добавлены страница `/students/clean/` со студентами без активных задолженностей
и страница `/debts/statistics/` со статистикой задолженностей. Ссылки на них
включены в общую навигацию. Для отсутствующих записей сохраняется ответ HTTP
404.

Консольное приложение продолжает работать с JSON. Веб-интерфейс читает
подготовленный файл SQLite, поэтому изменения, внесённые через консольную
версию, появляются на сайте после повторного импорта.

## 6. Проверка результата

Тесты в `tests/test_database.py` проверяют схему и внешние ключи, импорт
исходных данных, повторный импорт, сохранение базы при ошибке и выполнение всех
12 запросов из `sql/queries.sql`. Веб-тесты дополнены проверками страниц
студентов без долгов и статистики задолженностей.
